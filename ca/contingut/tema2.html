Tema 2: Components del Llenguatge i Control de Flux

2.1. Scripts de Python vs. Execució interactiva

En el Tema 1 es va presentar la sessió interactiva de Python (REPL), útil per explorar i provar idees al moment. En la pràctica, però, la major part del treball real es realitza mitjançant scripts: fitxers de text amb extensió .py que contenen un programa complet, pensat per executar-se de principi a fi.

2.1.1 La sessió interactiva (REPL)

La sessió interactiva permet executar instruccions una a una i veure el resultat de manera immediata:

>>> 2 + 3
5
>>> x = 10
>>> x * x
100

És ideal per explorar la sintaxi, comprovar el comportament d’una funció o fer càlculs ràpids. Però té una limitació fonamental: el codi no es desa. En tancar la sessió, tot el treball desapareix.

En l’entorn de desenvolupament integrat (IDE) Visual Studio Code, la sessió interactiva es pot obrir des del terminal amb la comanda python. Per acabar la sessió es pot usar exit().

2.1.2 Scripts .py

Un script de Python és un fitxer de text amb extensió .py que conté instruccions Python que s’executen seqüencialment. A diferència del REPL, un script es desa en disc, es pot reutilitzar en qualsevol moment, compartir amb altres persones i executar en entorns diferents.

REPL per explorar, scripts per produir. Usa la sessió interactiva per comprovar comportaments o fer càlculs puntuals. Escriu scripts quan vulguis desar, reproduir o compartir la teva feina. En la pràctica, les dues eines s’usen de manera complementària.

2.1.3 Notebooks: Jupyter i Marimo

Els notebooks són un format intermedi que combina característiques del REPL i els scripts. Un notebook es divideix en cel·les que es poden executar de forma individual i en qualsevol ordre; l’estat (variables, importacions) persisteix entre cel·les durant la sessió, i el fitxer es desa amb el codi i les seves sortides. A més, les cel·les poden contenir text enriquit en Markdown, equacions en LaTeX o gràfics, la qual cosa els converteix en una eina natural per comunicar resultats juntament amb el codi que els produeix.

Jupyter Notebook és el format més estès en ciència de dades i recerca. Els seus fitxers tenen extensió .ipynb i es poden executar al navegador, a VS Code o en plataformes com Google Colab. El principal inconvenient de Jupyter és que l’ordre d’execució de les cel·les és lliure, la qual cosa pot generar estats inconsistents difícils de depurar.

Marimo és una alternativa més recent i reactiva: les cel·les declaren les seves dependències explícitament, de manera que si es modifica una variable totes les cel·les que l’usen es recalculen automàticament. Això elimina els problemes d’estat inconsistent i fa que un notebook de Marimo sigui sempre reproduïble de dalt a baix, com un script.

En aquest curs es treballarà principalment amb scripts .py o notebooks Marimo en un Codespace (Temes 1–6). Els notebooks Marimo s’empren de forma natural en el Tema 7 en introduir NumPy, Pandas i Matplotlib, on la visualització de resultats integrada en un document és especialment útil.

2.2. Variables i els seus tipus

2.2.1 Variables

Fonament Teòric 1: Variable

En ciència de la computació, una variable és una associació entre un nom simbòlic i una ubicació en memòria que emmagatzema un valor que pot canviar durant l’execució del programa.

La definició més precisa distingeix tres components:

  • Nom (o identificador): la cadena de caràcters (pot ser només un) amb la qual el programador es refereix a la variable en el codi font.
  • Valor: el dato emmagatzemat en aquell moment.
  • Ubicació: l’adreça de memòria on resideix aquell dato.

Aquesta triple associació nom–valor–ubicació és el que defineix formalment una variable. El que varia entre llenguatges és quant d’això és visible o controlable pel programador.

En llenguatges com C, la variable és la ubicació: declarar int x reserva una cel·la de memòria i x és el nom d’aquella cel·la. En Python, en canvi, la variable és només el nom: el que canvia és a quin objecte apunta aquell nom en memòria, no la cel·la en si. Per entendre-ho fàcilment, s’acostuma a usar la metàfora de les “caixes” davant de les “etiquetes”.

En Python les variables són en realitat noms o referències que apunten a objectes. Tot en Python és un objecte (fins i tot els nombres simples).

Quan escrius x = 10, Python:

  1. Crea un objecte en la memòria que representa el nombre enter 10.
  2. Crea el nom x com si fos una etiqueta (un post-it).
  3. Enganxa l’etiqueta x sobre l’objecte 10.

Si després escrius y = x, Python no copia l’objecte. Simplement pren una nova etiqueta anomenada y i l’enganxa en el mateix objecte 10. Les dues variables apunten exactament al mateix lloc en la memòria.

NotaDiferència amb les variables matemàtiques

Una variable en programació no és el mateix que una variable matemàtica. L’exemple clàssic es mostra en la ruptura lògica de \(x = x + 1\)

  • En matemàtiques: L’expressió \(x = x + 1\) és una contradicció. Si intentes resoldre-la restant \(x\) als dos costats, arribes a l’absurd lògic de \(0 = 1\). El símbol \(=\) representa una equivalència permanent.
  • En programació: La instrucció x = x + 1 és una de les operacions més comunes que existeixen. El símbol = (en la majoria de llenguatges) no significa “equivalència”, sinó assignació. La instrucció es llegeix en el temps: “Avalua l’estat actual de \(x\), suma-li \(1\), i actualitza l’estat desant el nou resultat a \(x\)”.

Tenim doncs que en Python una variable és un nom que referencia un valor d’un cert tipus emmagatzemat en memòria. En Python les variables no tenen un tipus fix, poden referenciar valors de qualsevol tipus, i poden canviar de tipus al llarg de l’execució.

Fonament Teòric 2: Tipus

Un tipus de dada o simplement tipus és una classificació que especifica quins valors pot prendre una dada i quines operacions són vàlides sobre ella.

Per exemple, el tipus int (enter) admet els valors …−2, −1, 0, 1, 2… i operacions com suma o divisió entera; el tipus str (cadena o string en anglès) admet seqüències de caràcters i operacions com concatenació o indexació. Una operació invàlida per al tipus —sumar un enter amb una cadena sense conversió explícita— produeix un error.

En Python el tipus no el declara el programador: el determina el propi objecte. Cada objecte porta consigo el seu tipus, i type(x) el retorna en qualsevol moment.

L’assignació d’un valor a una variable (en Python, un enllaç de nom o name binding en anglès) es realitza amb l’operador =. A diferència d’altres llenguatges, = no copia un valor en una cel·la de memòria: fa que el nom de l’esquerra quedi apuntant a l’objecte produït per l’expressió de la dreta. Per exemple:

x = 42         # x referencia l'enter 42
print(x)       # 42
x = 3.14       # ara x referencia el flotant 3.14
print(x)       # 3.14
x = "hola"     # ara x referencia la cadena "hola"
print(x)       # hola
Concepte Clau 1: Comentaris en codi Python

En Python només existeix una forma de comentari: el símbol #. Tot el que va des d’allà fins al final de la línia ho ignora l’intèrpret. Un comentari és text inclòs en el codi font que va dirigit a qui el llegeix, no a la màquina que l’executa. El traductor —compilador o intèrpret— el descarta, de manera que la seva presència o absència no altera en res el comportament del programa.

Els comentaris poden aparèixer en una línia pròpia o a continuació del codi font en la mateixa línia. Les convencions de (Rossum, Warsaw, i Coghlan 2001) recomanen un espai després del #, i dos espais abans del # en els comentaris al final de línia.

2.2.2 Noms de variables

Els noms de variables només poden contenir lletres, dígits i el guió baix _, i no poden començar per un dígit ni coincidir amb una paraula reservada del llenguatge (if, for, while, True, False, None, etc.).

Concepte Clau 2: Convenció de noms: snake_case

Per convenció (Rossum, Warsaw, i Coghlan 2001), els noms de variables en Python usen snake_case: paraules en minúscules separades per guions baixos. Els noms han de ser descriptius del valor que contenen.

# Correcte
nombre_diteracions = 100
radi_cercle = 5.0
es_primer = True

# Acceptable per a variables de curta vida o amb significat matemàtic obvi
n = 100       # comptador genèric
x, y = 3, 4  # coordenades
i, j, k = 0, 0, 0  # índexs de bucles

# Evitar: noms sense significat
a1 = 100
cosa = True

2.3.3 Nombres complexos (complex)

Python incorpora els nombres complexos com a tipus natiu, sense necessitat d’importar cap biblioteca. La unitat imaginària es denota amb j (no i, per evitar conflicte amb l’ús de i com a índex en codi):

Els nombres complexos il·lustren bé un concepte central en Python: els objectes tenen atributs i mètodes als quals s’accedeix amb l’operador punt .:

  • Un atribut és un valor associat a l’objecte: z.real i z.imag retornen les parts real i imaginària del nombre complex z.
  • Un mètode és una funció associada a l’objecte que s’invoca amb parèntesis: z.conjugate() retorna el conjugat.

Aquesta notació objecte.algo apareixerà constantment en Python. En el Tema 5 s’estudiarà en detall què són els objectes i com es defineixen; per ara n’hi ha prou amb saber que tot valor en Python és un objecte i que el punt . dóna accés al que aquell objecte “sap fer”.

Els atributs .real i .imag retornen sempre float. Les operacions aritmètiques (+, -, *, /, **) funcionen directament entre complexos o entre complexos i enters/flotants.

La funció built-in abs() retorna el mòdul d’un nombre complex, que és la distància a l’origen en el pla complex. El mòdul es calcula com \(\sqrt{x^2 + y^2}\) per a un complex \(z = x + yi\). La funció abs() també funciona amb enters i flotants, retornant el seu valor absolut.

Per a càlculs més avançats amb nombres complexos (funcions trigonomètriques, logaritmes, exponencial complexa) s’usa el mòdul cmath de la biblioteca estàndard.

Un literal complex es forma combinant amb + o - un literal int o float com a part real i un literal int o float seguit de j com a part imaginària. La part imaginària és obligatòria; un literal com 3 o 2.5 és un int o float, no un complex.

2.4 Operadors aritmètics, de comparació (relacionals) i lògics

Python defineix set operadors aritmètics que funcionen principalment amb enters, flotants i complexos (int, float, complex). La taula següent resumeix el seu significat i comportament:

Operador Operació Exemple Resultat
+ Suma 7 + 3 10
- Resta 7 - 3 4
* Producte 7 * 3 21
/ Divisió real 7 / 3 2.3333…
// Divisió entera 7 // 3 2
% Mòdul (resta) 7 % 3 1
** Potència 2 ** 10 1024

Algunes excepcions i extensions d’aquests operadors segons el tipus de dada:

  • complex no admet // ni %, ja que la divisió entera i el mòdul no estan definits per a nombres complexos.
  • bool, en ser subtipus de int, hereta tots els operadors aritmètics.
  • str admet + com a concatenació i * com a repetició, però no la resta.

Per als tipus numèrics, quan es combinen operands de tipus diferents el resultat es promou al tipus més general. Per exemple, int + float produeix float, i int + complex produeix complex.

La potència ** admet exponents negatius i flotants, però el resultat és sempre float o complex. És a més l’únic operador amb associativitat per la dreta: 2 ** 3 ** 2 s’avalua com 2 ** 9 = 512.

Concepte Clau 4: Precedència d’operadors aritmètics

Python segueix les mateixes regles de precedència que la notació matemàtica estàndard. De major a menor prioritat:

  1. Parèntesis ()
  2. Potència **
  3. Signe unari +x, -x
  4. Producte *, divisions /, //, %
  5. Suma i resta +, -

Quan dos operadors tenen la mateixa precedència s’avaluen d’esquerra a dreta, excepte ** que és associatiu per la dreta. Els parèntesis permeten alterar qualsevol ordre d’avaluació.

Per a la divisió tenim dos operadors diferents: / i //. El primer retorna un flotant, mentre que el segon retorna el quocient enter (floor division). L’operador % retorna la resta (el mòdul) de la divisió entera.

L’operador // retorna el quocient enter (floor division) arrodonint cap a \(-\infty\), no cap a zero. L’operador % retorna la resta de la divisió entera:

Els operadors d’assignació composta combinen una operació aritmètica amb l’assignació, actualitzant la variable in situ:

Error Freqüent 2: Tractar l’aritmètica amb floats com la dels nombres reals

Com es va mostrar en error freqüent 1 l’aritmètica amb nombres float introdueix errors d’arrodoniment. Això es deu al fet que la representació binària dels flotants no pot expressar exactament tots els nombres reals. En Python s’empra l’aritmètica de punt flotant de doble precisió (IEEE 754), que té una precisió aproximada de 15-17 dígits decimals significatius.

En IEEE 754 doble precisió cada valor float es representa com:

\[ (-1)^s \times 1.m \times 2^e \]

on \(s\) és el signe, \(e\) l’exponent i \(1.m\) la mantissa amb el bit implícit de valor 1. Els 64 bits del float es reparteixen així:

Camp Bits Rang
Signe \(s\) 1 0 = positiu, 1 = negatiu
Exponent \(e\) 11 codificat en biaix (bias) de 1023
Mantissa \(m\) 52 part fraccionària després del bit implícit

Es recomana consultar (Python Software Foundation 2025) per a una explicació més detallada de l’aritmètica amb float i les seves implicacions en la pràctica.

2.4.2 Operadors de comparació (relacionals)

Els operadors de comparació o relacionals són fonamentals per al control de flux condicional: sense ells no hi ha manera que un programa prengui decisions. Constitueixen la base del mecanisme que dota a un programa d’adaptabilitat: en lloc d’executar sempre la mateixa seqüència d’instruccions, el programa examina l’estat de les dades en temps d’execució i tria el camí a seguir en conseqüència.

Els operadors de comparació avaluen una relació entre dos valors i retornen un booleà (True o False):

Operador Significat Exemple Resultat
== Igual a 3 == 3 True
!= Diferent de 3 != 4 True
< Menor que 2 < 5 True
> Major que 5 > 2 True
<= Menor o igual 3 <= 3 True
>= Major o igual 4 >= 5 False

Els operadors de comparació s’apliquen a tots els tipus simples, amb dues excepcions importants:

  • complex no admet <, >, <=, >=: els nombres complexos no tenen ordre total, igual que en matemàtiques. Només == i != estan definits.
  • str usa ordre lexicogràfic: les comparacions d’ordre segueixen el codi Unicode de cada caràcter, no l’ordre alfabètic intuïtiu. En particular, totes les majúscules precedeixen totes les minúscules: "Z" < "a" és True.

El fonament teòric dels operadors de comparació es troba en la matemàtica discreta, específicament en la teoria de les relacions binàries (derivada de la teoria de conjunts). Matemàticament, una relació binària \(R\) sobre un conjunt \(A\) és un subconjunt del producte cartesià \(A \times A\). En programació, el conjunt \(A\) representa el domini d’un tipus de dada específic (per exemple, int o float). Quan un programa avalua una expressió com x < y, està verificant si el parell ordenat \((x, y)\) pertany al conjunt definit per la relació matemàtica \(<\).

Relació d’Equivalència (==)

Perquè un operador d’igualtat tingui sentit lògic, es fonamenta en les tres propietats d’una relació d’equivalència:

  • Reflexivitat: \(x = x\) (Tot valor és igual a si mateix).
  • Simetria: Si \(x = y\), llavors \(y = x\).
  • Transitivitat: Si \(x = y\) i \(y = z\), llavors \(x = z\).

Aquestes propietats matemàtiques, com es va mencionar en error freqüent 1 i error freqüent 2, de vegades xoquen amb les representacions en memòria. Un altre exemple: en l’estàndard IEEE 754 per a coma flotant, el valor NaN (Not a Number) trenca intencionalment la reflexivitat, ja que NaN == NaN avalua a fals.

En Python 3, per defecte, != es comporta automàticament com la negació lògica de ==. No obstant això, a nivell d’arquitectura, són dues operacions independents i el llenguatge et permet trencar aquesta regla si ho desitges (això es veurà en el Tema 5, quan s’estudiïn les classes i la sobrecàrrega d’operadors).

Relacions d’Ordre (<, >, <=, >=)

Aquests operadors implementen el que en matemàtiques es coneix com una relació d’ordre (generalment un ordre total). Per a un operador d’ordre no estricte com <=, el llenguatge garanteix matemàticament:

  • Reflexivitat: \(x \le x\).
  • Antisimetria: Si \(x \le y\) i \(y \le x\), llavors \(x = y\).
  • Transitivitat: Si \(x \le y\) i \(y \le z\), llavors \(x \le z\).

Els operadors lògics (and, or, not) permeten construir condicions compostes (expressions lògiques) combinant expressions booleanes simples com les que s’obtenen usant els operadors de comparació. 2.5. Control de Flux — Estructures o Sentències Condicionals

El control de flux és el mecanisme que determina l’ordre en què s’avaluen les instruccions d’un programa. Tot i que per defecte l’execució segueix una seqüència estrictament lineal, les estructures de control permeten alterar aquesta trajectòria: bifurcar l’execució en funció d’una premissa lògica, o iterar repetidament sobre un bloc de codi. En aquest marc, les estructures condicionals actuen com l’eina fonamental per a la presa de decisions.

Fonament Teòric 6: Condicionals

Una estructura condicional o sentència condicional és una construcció del llenguatge que permet executar un bloc d’instruccions només si una expressió de condició s’avalua com a verdadera, i opcionalment executar un bloc alternatiu si s’avalua com a falsa. És el mecanisme fonamental mitjançant el qual un programa adapta el seu comportament a l’estat de les dades en temps d’execució.

Independentment del llenguatge de programació subjacent, tot condicional es fonamenta en dues peces clau:

  • El Predicat (La Condició): És l’expressió que el sistema avalua i que sempre s’ha de resoldre o mapejar a un estat booleà estricte (Vertader o Fals). Actua com la frontera o la “pregunta” que determina el camí a seguir.
  • Les Branques (Els Camins): Són els blocs de codi associats a cada possible resultat de la condició. Aquestes branques són mútuament excloents: el processador executarà únicament el conjunt d’instruccions associat a la branca vàlida i descartar silenciosament la resta.

A nivell del maquinari subjacent, un condicional es tradueix en una instrucció de salt (branching). El processador avalua l’estat d’un registre (per exemple, verificant si una resta dóna zero) i, basant-se en aquell resultat lògic, altera el Comptador de Programa per saltar a una adreça de memòria diferent en lloc de llegir la instrucció immediatament següent.

L’estructura condicional en Python és if, que admet tres formes:

  • if sol: executa un bloc si la condició és verdadera, i no fa res si és falsa.
  • if-else: afegeix un bloc alternatiu per quan la condició és falsa.
  • if-elif-else: encadena múltiples condicions mútuament excloents, avaluades en ordre fins que una sigui verdadera.

2.6. Control de Flux — Iteracions

La iteració és el mecanisme que permet repetir un bloc d’instruccions un nombre determinat de vegades o mentre es compleixi una condició. Sense iteració, un programa només podria processar una quantitat fixa de dades coneguda en temps d’escriptura; amb iteració pot operar sobre col·leccions de mida arbitrària, aproximar resultats mitjançant successions o sèries, i executar processos que convergeixen a una solució.

En matemàtiques la iteració té equivalents directes en la notació de sumatori \(\sum\), productori \(\prod\) i en la definició de successions per recurrència. Python proporciona dues estructures iteratives fonamentals: while, que repeteix mentre una condició sigui verdadera, i for, que recorre els elements d’una seqüència.

2.6.1 El bucle while (iteració indefinida o condicional)

El bucle while repeteix un bloc d’instruccions mentre una condició sigui verdadera. Representa el concepte clàssic de les ciències de la computació on l’execució d’un bloc de codi depèn de l’estat actual del programa. S’anomena “indefinit” perquè el nombre de repeticions pot ser desconegut en iniciar el bucle.

  • Fonament: Es basa exclusivament en l’avaluació d’una expressió booleana (la condició).
  • Mecanisme: Abans d’entrar al cicle i a l’inici de cada repetició posterior, l’intèrpret avalua la condició. Si el resultat és True, el bloc de codi s’executa. Si és False, el flux salta a la primera instrucció que estigui fora del bucle.
  • Teoria de l’estat: Perquè un bucle while sigui teòricament segur, l’estat del programa ha de canviar dins del bloc. Si l’estat no altera mai la condició d’avaluació, es produeix un bucle infinit.

Disseny correcte d’un bucle while

Perquè un bucle while funcioni de forma correcta i predictible cal atendre cinc aspectes:

  1. Inicialització: totes les variables de la condició han d’estar definides abans de la primera avaluació.
  2. Variant de bucle: una expressió entera que decreix estrictament en cada iteració i està acotada inferiorment, garantint que el bucle acaba. La seva existència prova que l’algoritme no és infinit.
  3. Invariant de bucle: una propietat lògica que és verdadera abans de la primera iteració i es manté verdadera al final de cada una. La seva preservació garanteix que el bucle calcula el que es pretén calcular.
  4. Casos límit: la condició ha de gestionar de forma segura valors extrems o nuls per evitar errors en temps d’execució.
  5. break i continue amb moderació: el seu abús trenca el flux d’entrada i sortida única, dificultant la lectura i el raonament sobre el codi.
Fonament Teòric 7: Variant de bucle

Una variant de bucle (loop variant) és una expressió de valor enter no negatiu associada a un bucle que satisfà dues condicions:

  1. Decreix estrictament en cada iteració: el seu valor després d’executar el cos del bucle és estrictament menor que el seu valor abans.
  2. Està acotada inferiorment per zero: no pot prendre valors negatius.

Aquestes dues condicions juntes garanteixen que el bucle acaba en un nombre finit d’iteracions, ja que una successió d’enters no negatius que decreix estrictament no pot ser infinita.

En la pràctica, la variant sol ser un comptador, la distància entre dos valors que convergeixen, o el nombre d’elements que queden per processar. Per exemple, en un bucle que recorre els dígits d’un enter n dividint-lo per 10 en cada iteració, la variant és el propi valor de n: decreix estrictament i arriba a 0 en un nombre finit de passos. L’existència d’una variant de bucle és l’eina formal per demostrar que un bucle acaba.

Fonament Teòric 8: Invariant de bucle

Un invariant de bucle (loop invariant) és una propietat lògica sobre l’estat del programa que és verdadera abans de la primera iteració i es manté verdadera al final de cada iteració. Com a conseqüència, també és verdadera quan el bucle acaba, moment en què —combinada amb la negació de la condició del while— permet deduir que el resultat calculat és correcte.

L’invariant captura formalment què fa el bucle: no com ho fa pas a pas, sinó quina propietat acumula o preserva en cada iteració. Per exemple, en un bucle que calcula la suma \(\sum_{k=1}^{n} k\), l’invariant és que al final de la iteració \(i\) la variable suma conté el valor \(\sum_{k=1}^{i} k\).

L’existència d’un invariant de bucle vàlid és l’eina formal per demostrar que un bucle calcula el que es pretén calcular, és a dir, la seva correcció parcial.

La variant i l’invariant de bucle són les eines teòriques fonamentals del raonament formal sobre bucles. La variant garanteix que el bucle acaba; l’invariant garanteix que calcula el correcte. Si es pot exhibir una variant i un invariant vàlids, s’ha provat rigorosament que el bucle acaba i que el seu resultat és l’esperat.

2.6.2 El bucle for (iteració definida) i l’objecte range()

El bucle for en Python itera sobre els elements d’una seqüència, per això es diu que és una iteració definida. Aquest és un cas on Python difereix conceptualment de llenguatges com C o C++. En aquells llenguatges, un for sol ser un while disfressat amb un comptador numèric (ex. for(i=0; i<10; i++)).

En Python, el for és en realitat un bucle “for-each” (per a cada element). La seva base no és una condició matemàtica, sinó el consum sistemàtic dels elements d’un objecte iterable. Un objecte iterable és qualsevol objecte que pot lliurar els seus elements d’un en un en un ordre definit i sobre el qual es pot usar un bucle for.

L’exemple més immediat d’objecte iterable són els objectes de la classe range. Mitjançant objectes range es generen seqüències d’enters que constitueixen la forma habitual de controlar el nombre de repeticions en un bucle for.

El tipus range() genera seqüències d’enters de les tres formes següents:

Crida Seqüència generada
range(n) 0, 1, 2, …, n−1
range(a, b) a, a+1, …, b−1
range(a, b, pas) a, a+pas, a+2·pas, … mentre el valor sigui < b
Concepte Clau 7: L’anatomia de l’objecte range

Quan escrius r = range(0, 10, 2), Python no crea ni emmagatzema en memòria una seqüència amb els nombres 0, 2, 4, 6, 8. Això seria ineficient. En el seu lloc, l’objecte range només emmagatzema tres enters:

  • start (inici)
  • stop (fi)
  • step (salt)

Els enters es produeixen d’un en un a mesura que el bucle els sol·licita (lazy evaluation). Gràcies a això, range(10) i range(1000000000) ocupen exactament la mateixa quantitat mínima de memòria.

2.7.2 Cadenes formatades: f-strings

Les f-strings (cadenes formatades) són la forma més moderna, llegible i ràpida d’inserir variables i expressions dins de cadenes de text en Python. S’escriuen amb el prefix f (o F) just abans de les cometes (simples o dobles) i empren claus {} per indicar on s’ha d’injectar el valor d’una variable o una expressió.

El veritable avantatge de les f-strings no és només inserir variables estàtiques; permeten executar codi Python vàlid directament dins de les claus. És possible fer càlculs matemàtics, cridar mètodes o usar funcions sense necessitat de crear variables temporals prèvies.

A partir de Python 3.8 es pot afegir un signe igual = després del nom de la variable (o expressió) dins de les claus. Això imprimeix tant el nom de la variable com el seu valor resultant, la qual cosa estalvia molt de temps en fer depuració (debugging) amb print().

NotaEspecificadors de format en f-strings

Els especificadors de format en una f-string s’escriuen dins de {} i permeten controlar la presentació del valor:

Especificador Efecte Exemple Resultat
:.nf n decimals fixos f"{3.14159:.2f}" 3.14
:e Notació científica f"{12345.6:.3e}" 1.235e+04
:g Decimal o científica segons magnitud f"{0.000123:.3g}" 0.000123
:d Enter decimal f"{42:d}" 42
:>n Alineat a la dreta en amplada n f"{7:>6d}" 7
:<n Alineat a l’esquerra en amplada n f"{'abc':<6}" abc
:0n Farcit amb zeros f"{7:06d}" 000007
:, Separador de milers f"{1000000:,}" 1,000,000

2.7.3 La funció input()

input() atura l’execució del programa, mostra un missatge opcional en pantalla i espera que l’usuari escrigui alguna cosa i premi Retorn. Sempre retorna una cadena de text (str), independentment del que l’usuari hagi escrit.

text = input("Escriu alguna cosa: ")
print(f"Has escrit: {text}")
print(type(text))              # <class 'str'>

Per treballar amb valors numèrics, cal convertir la cadena retornada per input():

n = int(input("Introdueix un nombre enter: "))
print(f"El quadrat de {n} és {n**2}.")

x = float(input("Introdueix un nombre real: "))
print(f"La seva arrel quadrada és {x**0.5:.6f}.")
Error Freqüent 5: Oblidar que input() sempre retorna str

Un dels errors més comuns en començar amb Python:

n = input("Introdueix n: ")
resultat = n + 1     # TypeError: can only concatenate str (not "int") to str

La solució és convertir explícitament el tipus abans d’operar:

n = int(input("Introdueix n: "))
resultat = n + 1     # correcte
Exemple 6: Calculadora interactiva

Implementem una calculadora bàsica que sol·licita dos nombres i una operació a l’usuari, i després mostra el resultat:

print("=== Calculadora bàsica ===")
a = float(input("Primer nombre: "))
b = float(input("Segon nombre: "))
op = input("Operació (+, -, *, /): ")

if op == "+":
    resultat = a + b
elif op == "-":
    resultat = a - b
elif op == "*":
    resultat = a * b
elif op == "/":
    if b != 0:
        resultat = a / b
    else:
        print("Error: divisió per zero.")
        resultat = None
else:
    print(f"Operació '{op}' no reconeguda.")
    resultat = None

if resultat is not None:
    print(f"{a} {op} {b} = {resultat:.6g}")

Per provar els exemples d’ús de la funció input(), cal executar el codi en un entorn que suporti l’entrada interactiva, com un IDE (Visual Studio Code local o en un Codespace de GitHub) que permeti la interacció amb l’usuari. En entorns d’execució no interactius, com alguns notebooks o plataformes en línia, la funció input() pot no funcionar correctament.
