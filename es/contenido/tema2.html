Tema 2: Componentes del Lenguaje y Control de Flujo

2.1. Scripts de Python vs. Ejecución interactiva

En el Tema 1 se presentó la sesión interactiva de Python (REPL), útil para explorar y probar ideas al vuelo. En la práctica, sin embargo, la mayor parte del trabajo real se realiza mediante scripts: archivos de texto con extensión .py que contienen un programa completo, pensado para ejecutarse de principio a fin.

2.1.1 La sesión interactiva (REPL)

La sesión interactiva permite ejecutar instrucciones una a una y ver el resultado de inmediato:

>>> 2 + 3
5
>>> x = 10
>>> x * x
100

Es ideal para explorar la sintaxis, comprobar el comportamiento de una función o hacer cálculos rápidos. Pero tiene una limitación fundamental: el código no se guarda. Al cerrar la sesión, todo el trabajo desaparece.

En el entorno de desarrollo integrado (IDE) Visual Studio Code, la sesión interactiva se puede abrir desde la terminal con el comando python. Para terminar la sesión se puede usar exit().

2.1.2 Scripts .py

Un script de Python es un archivo de texto con extensión .py que contiene instrucciones Python que se ejecutan secuencialmente. A diferencia del REPL, un script se guarda en disco, puede reutilizarse en cualquier momento, compartirse con otras personas y ejecutarse en distintos entornos.

REPL para explorar, scripts para producir. Usa la sesión interactiva para comprobar comportamientos o hacer cálculos puntuales. Escribe scripts cuando quieras guardar, reproducir o compartir tu trabajo. En la práctica, ambas herramientas se usan de forma complementaria.

2.1.3 Notebooks: Jupyter y Marimo

Los notebooks son un formato intermedio que combina características del REPL y los scripts. Un notebook se divide en celdas que pueden ejecutarse de forma individual y en cualquier orden; el estado (variables, importaciones) persiste entre celdas durante la sesión, y el archivo se guarda con el código y sus salidas. Además, las celdas pueden contener texto enriquecido en Markdown, ecuaciones en LaTeX o gráficos, lo que los convierte en una herramienta natural para comunicar resultados junto al código que los produce.

Jupyter Notebook es el formato más extendido en ciencia de datos e investigación. Sus archivos tienen extensión .ipynb y pueden ejecutarse en el navegador, en VS Code o en plataformas como Google Colab. El principal inconveniente de Jupyter es que el orden de ejecución de las celdas es libre, lo que puede generar estados inconsistentes difíciles de depurar.

Marimo es una alternativa más reciente y reactiva: las celdas declaran sus dependencias explícitamente, de modo que si se modifica una variable todas las celdas que la usan se recalculan automáticamente. Esto elimina los problemas de estado inconsistente y hace que un notebook de Marimo sea siempre reproducible de arriba abajo, como un script.

En este curso se trabajará principalmente con scripts .py o notebooks Marimo en un Codespace (Temas 1–6). Los notebooks Marimo se emplean de forma natural en el Tema 7 al introducir NumPy, Pandas y Matplotlib, donde la visualización de resultados integrada en un documento es especialmente útil.

2.2. Variables y sus tipos

2.2.1 Variables

Fundamento Teórico 1: Variable

En ciencia de la computación, una variable es una asociación entre un nombre simbólico y una ubicación en memoria que almacena un valor que puede cambiar durante la ejecución del programa.

La definición más precisa distingue tres componentes:

  • Nombre (o identificador): la cadena de caracteres (puede ser solo uno) con el que el programador se refiere a la variable en el código fuente.
  • Valor: el dato almacenado en ese momento.
  • Ubicación: la dirección de memoria donde reside ese dato.

Esta triple asociación nombre–valor–ubicación es lo que define formalmente una variable. Lo que varía entre lenguajes es cuánto de esto es visible o controlable por el programador.

En lenguajes como C, la variable es la ubicación: declarar int x reserva una celda de memoria y x es el nombre de esa celda. En Python, en cambio, la variable es solo el nombre: lo que cambia es a qué objeto apunta ese nombre en memoria, no la celda en sí. Para entenderlo fácilmente, se suele usar la metáfora de las “cajas” frente a las “etiquetas”.

En Python las variables son en realidad nombres o referencias que apuntan a objetos. Todo en Python es un objeto (incluso los números simples).

Cuando escribes x = 10, Python:

  1. Crea un objeto en la memoria que representa al número entero 10.
  2. Crea el nombre x como si fuera una etiqueta (un post-it).
  3. Pega la etiqueta x sobre el objeto 10.

Si después escribes y = x, Python no copia el objeto. Simplemente toma una nueva etiqueta llamada y y la pega en el mismo objeto 10. Ambas variables apuntan exactamente al mismo lugar en la memoria.

NotaDiferencia con las variables matemáticas

Una variable en programación no es lo mismo que una variable matemática. El clásico ejemplo se muestra en la ruptura lógica de \(x = x + 1\)

  • En matemáticas: La expresión \(x = x + 1\) es una contradicción. Si intentas resolverla restando \(x\) en ambos lados, llegas al absurdo lógico de \(0 = 1\). El símbolo \(=\) representa una equivalencia permanente.
  • En programación: La instrucción x = x + 1 es una de las operaciones más comunes que existen. El símbolo = (en la mayoría de lenguajes) no significa “equivalencia”, sino asignación. La instrucción se lee en el tiempo: “Evalúa el estado actual de \(x\), súmale \(1\), y actualiza el estado guardando el nuevo resultado en \(x\)”.

Tenemos entonces que en Python una variable es un nombre que referencia un valor de cierto tipo almacenado en memoria. En Python las variables no tienen un tipo fijo, pueden referenciar valores de cualquier tipo, y pueden cambiar de tipo a lo largo de la ejecución.

Fundamento Teórico 2: Tipo

Un tipo de dato o simplemente tipo es una clasificación que especifica qué valores puede tomar un dato y qué operaciones son válidas sobre él.

Por ejemplo, el tipo int (entero) admite los valores …−2, −1, 0, 1, 2… y operaciones como suma o división entera; el tipo str (cadena o string en inglés) admite secuencias de caracteres y operaciones como concatenación o indexación. Una operación inválida para el tipo —sumar un entero con una cadena sin conversión explícita— produce un error.

En Python el tipo no lo declara el programador: lo determina el objeto en sí. Cada objeto lleva consigo su tipo, y type(x) lo devuelve en cualquier momento.

La asignación de un valor a una variable (en Python, un enlace de nombre o name binding en inglés) se realiza con el operador =. A diferencia de otros lenguajes, = no copia un valor en una celda de memoria: hace que el nombre de la izquierda quede apuntando al objeto producido por la expresión de la derecha. Por ejemplo:

x = 42         # x referencia el entero 42
print(x)       # 42
x = 3.14       # ahora x referencia el flotante 3.14
print(x)       # 3.14
x = "hola"     # ahora x referencia la cadena "hola"
print(x)       # hola
Concepto Clave 1: Comentarios en código Python

En Python sólo existe una forma de comentario: el símbolo #. Todo lo que va desde ahí hasta el final de la línea lo ignora el intérprete. Un comentario es texto incluido en el código fuente que va dirigido a quien lo lee, no a la máquina que lo ejecuta. El traductor —compilador o intérprete— lo descarta, de modo que su presencia o ausencia no altera en nada el comportamiento del programa.

Los comentarios pueden aparecer en una línea propia o a continuación del código fuente en la misma línea. Las convenciones de (Rossum, Warsaw, y Coghlan 2001) recomiendan un espacio tras el #, y dos espacios antes del # en los comentarios al final de línea.

Python admite asignación múltiple en una sola línea:

La función print() puede recibir varias variables como argumentos, separadas por comas, y las imprime en la salida estándar (normalmente la terminal). Más adelante se verá que print() tiene parámetros opcionales para controlar el formato de salida.

2.2.2 Nombres de variables

Los nombres de variables solo pueden contener letras, dígitos y el guión bajo _, y no pueden comenzar por un dígito ni coincidir con una palabra reservada del lenguaje (if, for, while, True, False, None, etc.).

Concepto Clave 2: Convención de nombres: snake_case

Por convenio (Rossum, Warsaw, y Coghlan 2001), los nombres de variables en Python usan snake_case: palabras en minúsculas separadas por guiones bajos. Los nombres deben ser descriptivos del valor que contienen.

# Correcto
numero_de_iteraciones = 100
radio_circulo = 5.0
es_primo = True

# Aceptable para variables de corta vida o con significado matemático obvio
n = 100       # contador genérico
x, y = 3, 4  # coordenadas
i, j, k = 0, 0, 0  # índices de bucles

# Evitar: nombres sin significado
a1 = 100
cosa = True

2.3.3 Números complejos (complex)

Python incorpora los números complejos como tipo nativo, sin necesidad de importar ninguna librería. La unidad imaginaria se denota con j (no i, para evitar conflicto con el uso de i como índice en código):

Los números complejos ilustran bien un concepto central en Python: los objetos tienen atributos y métodos a los que se accede con el operador punto .:

  • Un atributo es un valor asociado al objeto: z.real y z.imag devuelven las partes real e imaginaria del número complejo z.
  • Un método es una función asociada al objeto que se invoca con paréntesis: z.conjugate() devuelve el conjugado.

Esta notación objeto.algo aparecerá constantemente en Python. En el Tema 5 se estudiará en detalle qué son los objetos y cómo se definen; por ahora basta con saber que todo valor en Python es un objeto y que el punto . da acceso a lo que ese objeto “sabe hacer”.

Los atributos .real e .imag devuelven siempre float. Las operaciones aritméticas (+, -, *, /, **) funcionan directamente entre complejos o entre complejos y enteros/flotantes.

La función built-in abs() devuelve el módulo de un número complejo, que es la distancia al origen en el plano complejo. El módulo se calcula como \(\sqrt{x^2 + y^2}\) para un complejo \(z = x + yi\). La función abs() también funciona con enteros y flotantes, devolviendo su valor absoluto.

Para cálculos más avanzados con números complejos (funciones trigonométricas, logaritmos, exponencial compleja) se usa el módulo cmath de la librería estándar.

Un literal complex se forma combinando con + o - un literal int o float como parte real y un literal int o float seguido de j como parte imaginaria. La parte imaginaria es obligatoria; un literal como 3 o 2.5 es un int o float, no un complex.

2.4 Operadores aritméticos, de comparación (relacionales) y lógicos

Python define siete operadores aritméticos que funcionan principalmente con enteros, flotantes y complejos (int, float, complex). La tabla siguiente resume su significado y comportamiento:

Operador Operación Ejemplo Resultado
+ Suma 7 + 3 10
- Resta 7 - 3 4
* Producto 7 * 3 21
/ División real 7 / 3 2.3333…
// División entera 7 // 3 2
% Módulo (resto) 7 % 3 1
** Potencia 2 ** 10 1024

Algunas excepciones y extensiones de estos operadores según el tipo de dato son:

  • complex no admite // ni %, ya que la división entera y el módulo no están definidos para números complejos.
  • bool, al ser subtipo de int, hereda todos los operadores aritméticos.
  • str admite + como concatenación y * como repetición, pero no el resto.

Para los tipos numéricos, cuando se combinan operandos de tipos distintos el resultado se promueve al tipo más general. Por ejemplo, int + float produce float, y int + complex produce complex.

La potencia ** admite exponentes negativos y flotantes, pero el resultado es siempre float o complex. Es además el único operador con asociatividad por la derecha: 2 ** 3 ** 2 se evalúa como 2 ** 9 = 512.

Concepto Clave 4: Precedencia de operadores aritméticos

Python sigue las mismas reglas de precedencia que la notación matemática estándar. De mayor a menor prioridad:

  1. Paréntesis ()
  2. Potencia **
  3. Signo unario +x, -x
  4. Producto *, divisiones /, //, %
  5. Suma y resta +, -

Cuando dos operadores tienen la misma precedencia se evalúan de izquierda a derecha, excepto ** que es asociativo por la derecha. Los paréntesis permiten alterar cualquier orden de evaluación.

Para la división tenemos dos operadores distintos: / y //. El primero devuelve un flotante, mientras que el segundo devuelve el cociente entero (floor division). El operador % devuelve el resto (el módulo) de la división entera.

El operador // devuelve el cociente entero (floor division) redondeando hacia \(-\infty\), no hacia cero. El operador % devuelve el resto de la división entera:

Se cumple siempre la identidad: a == (a // b) * b + (a % b). Aquí == es un operador de comparación (igualdad), no de asignación. Por ejemplo:

Error Frecuente 2: Tratar la aritmética con floats como la de números reales

Como se mostró en error frecuente 1 la aritmética con números float introduce errores de redondeo. Esto se debe a que la representación binaria de los flotantes no puede expresar exactamente todos los números reales. En Python se emplea la aritmética de punto flotante de doble precisión (IEEE 754), que tiene una precisión aproximada de 15-17 dígitos decimales significativos.

En IEEE 754 doble precisión cada valor float se representa como:

\[ (-1)^s \times 1.m \times 2^e \]

donde \(s\) es el signo, \(e\) el exponente y \(1.m\) la mantisa con el bit implícito de valor 1. Los 64 bits del float se reparten así:

Campo Bits Rango
Signo \(s\) 1 0 = positivo, 1 = negativo
Exponente \(e\) 11 codificado en sesgo (bias) de 1023
Mantisa \(m\) 52 parte fraccionaria tras el bit implícito

Se recomienda consultar (Python Software Foundation 2025) para una explicación más detallada de la aritmética con float y sus implicaciones en la práctica.

2.4.2 Operadores de comparación (relacionales)

Los operadores de comparación o relacionales son fundamentales para el control de flujo condicional: sin ellos no hay forma de que un programa tome decisiones. Constituyen la base del mecanismo que dota a un programa de adaptabilidad: en lugar de ejecutar siempre la misma secuencia de instrucciones, el programa examina el estado de los datos en tiempo de ejecución y elige el camino a seguir en consecuencia.

Los operadores de comparación evalúan una relación entre dos valores y devuelven un booleano (True o False):

Operador Significado Ejemplo Resultado
== Igual a 3 == 3 True
!= Distinto de 3 != 4 True
< Menor que 2 < 5 True
> Mayor que 5 > 2 True
<= Menor o igual 3 <= 3 True
>= Mayor o igual 4 >= 5 False

Los operadores de comparación se aplican a todos los tipos simples, con dos excepciones importantes:

  • complex no admite <, >, <=, >=: los números complejos no tienen orden total, igual que en matemáticas. Solo == y != están definidos.
  • str usa orden lexicográfico: las comparaciones de orden siguen el código Unicode de cada carácter, no el orden alfabético intuitivo. En particular, todas las mayúsculas preceden a todas las minúsculas: "Z" < "a" es True.
Error Frecuente 3: Comparar tipos distintos

Comparar valores de tipos distintos con == no produce error sino False directamente (42 == "42" es False). Usar < o > entre tipos incompatibles sí lanza TypeError.

Fundamento Teórico 3: Operadores de comparación

El fundamento teórico de los operadores de comparación se encuentra en la matemática discreta, específicamente en la teoría de las relaciones binarias (derivada de la teoría de conjuntos). Matemáticamente, una relación binaria \(R\) sobre un conjunto \(A\) es un subconjunto del producto cartesiano \(A \times A\). En programación, el conjunto \(A\) representa el dominio de un tipo de dato específico (por ejemplo, int o float). Cuando un programa evalúa una expresión como x < y, está verificando si el par ordenado \((x, y)\) pertenece al conjunto definido por la relación matemática \(<\).

Estos operadores se dividen en dos familias basadas en sus propiedades teóricas:

Relación de Equivalencia (==)

Para que un operador de igualdad tenga sentido lógico, se fundamenta en las tres propiedades de una relación de equivalencia:

  • Reflexividad: \(x = x\) (Todo valor es igual a sí mismo).
  • Simetría: Si \(x = y\), entonces \(y = x\).
  • Transitividad: Si \(x = y\) e \(y = z\), entonces \(x = z\).

Estas propiedades matemáticas, como se mencionó en error frecuente 1 y error frecuente 2, a veces chocan con las representaciones en memoria. Otro ejemplo, en el estándar IEEE 754 para coma flotante, el valor NaN (Not a Number) rompe intencionalmente la reflexividad, ya que NaN == NaN evalúa a falso.

En Python 3, por defecto, != se comporta automáticamente como la negación lógica de ==. Sin embargo, a nivel de arquitectura, son dos operaciones independientes y el lenguaje te permite romper esa regla si lo deseas (esto se verá en el Tema 5, cuando se estudien las clases y la sobrecarga de operadores).

Relaciones de Orden (<, >, <=, >=)

Estos operadores implementan lo que en matemáticas se conoce como una relación de orden (generalmente un orden total). Para un operador de orden no estricto como <=, el lenguaje garantiza matemáticamente:

  • Reflexividad: \(x \le x\).
  • Antisimetría: Si \(x \le y\) y \(y \le x\), entonces \(x = y\).
  • Transitividad: Si \(x \le y\) y \(y \le z\), entonces \(x \le z\).

2.5. Control de Flujo — Estructuras o Sentencias Condicionales

El control de flujo es el mecanismo que determina el orden en el que se evalúan las instrucciones de un programa. Aunque por defecto la ejecución sigue una secuencia estrictamente lineal, las estructuras de control permiten alterar esta trayectoria: bifurcar la ejecución en función de una premisa lógica, o iterar repetidamente sobre un bloque de código. En este marco, las estructuras condicionales actúan como la herramienta fundamental para la toma de decisiones.

Fundamento Teórico 6: Condicionales

Una estructura condicional o sentencia condicional es una construcción del lenguaje que permite ejecutar un bloque de instrucciones solo si una expresión de condición se evalúa como verdadera, y opcionalmente ejecutar un bloque alternativo si se evalúa como falsa. Es el mecanismo fundamental mediante el cual un programa adapta su comportamiento al estado de los datos en tiempo de ejecución.

Independientemente del lenguaje de programación subyacente todo condicional se fundamenta en dos piezas clave:

  • El Predicado (La Condición): Es la expresión que el sistema evalúa y que siempre debe resolverse o mapearse a un estado booleano estricto (Verdadero o Falso). Actúa como la frontera o la “pregunta” que determina el camino a seguir.
  • Las Ramas (Los Caminos): Son los bloques de código asociados a cada posible resultado de la condición. Estas ramas son mutuamente excluyentes: el procesador ejecutará únicamente el conjunto de instrucciones asociado a la rama válida y descartará silenciosamente el resto.

A nivel del hardware subyacente, un condicional se traduce en una instrucción de salto (branching). El procesador evalúa el estado de un registro (por ejemplo, verificando si una resta da cero) y, basándose en ese resultado lógico, altera el Contador de Programa para saltar a una dirección de memoria diferente en lugar de leer la instrucción inmediatamente siguiente.

La estructura condicional en Python es if, que admite tres formas:

  • if solo: ejecuta un bloque si la condición es verdadera, y no hace nada si es falsa.
  • if-else: añade un bloque alternativo para cuando la condición es falsa.
  • if-elif-else: encadena múltiples condiciones mutuamente excluyentes, evaluadas en orden hasta que una sea verdadera.

2.6. Control de Flujo — Iteraciones

La iteración es el mecanismo que permite repetir un bloque de instrucciones un número determinado de veces o mientras se cumpla una condición. Sin iteración, un programa solo podría procesar una cantidad fija de datos conocida en tiempo de escritura; con iteración puede operar sobre colecciones de tamaño arbitrario, aproximar resultados mediante sucesiones o series, y ejecutar procesos que convergen a una solución.

En matemáticas la iteración tiene equivalentes directos en la notación de sumatorio \(\sum\), productorio \(\prod\) y en la definición de sucesiones por recurrencia. Python proporciona dos estructuras iterativas fundamentales: while, que repite mientras una condición sea verdadera, y for, que recorre los elementos de una secuencia.

2.6.1 El bucle while (iteración indefinida o condicional)

El bucle while repite un bloque de instrucciones mientras una condición sea verdadera. ERepresenta el concepto clásico de las ciencias de la computación donde la ejecución de un bloque de código depende del estado actual del programa. Se le llama “indefinido” porque el número de repeticiones puede ser desconocido al iniciar el bucle.

  • Fundamento: Se basa exclusivamente en la evaluación de una expresión booleana (la condición).
  • Mecanismo: Antes de entrar al ciclo y al inicio de cada repetición posterior, el intérprete evalúa la condición. Si el resultado es True, el bloque de código se ejecuta. Si es False, el flujo salta a la primera instrucción que esté fuera del bucle.
  • Teoría del estado: Para que un bucle while sea teóricamente seguro, el estado del programa debe cambiar dentro del bloque. Si el estado nunca altera la condición de evaluación, se produce un bucle infinito.
while condición:
    # bloque que se repite

  • break: interrumpe el bucle inmediatamente y salta al código que viene después.

Diseño correcto de un bucle while

Para que un bucle while funcione de forma correcta y predecible hay que atender cinco aspectos:

  1. Inicialización: todas las variables de la condición deben estar definidas antes de la primera evaluación.
  2. Variante de bucle: una expresión entera que decrece estrictamente en cada iteración y está acotada inferiormente, garantizando que el bucle termina. Su existencia prueba que el algoritmo no es infinito.
  3. Invariante de bucle: una propiedad lógica que es verdadera antes de la primera iteración y se mantiene verdadera al final de cada una. Su preservación garantiza que el bucle calcula lo que se pretende calcular.
  4. Casos límite: la condición debe manejar de forma segura valores extremos o nulos para evitar errores en tiempo de ejecución.
  5. break y continue con moderación: su abuso rompe el flujo de entrada y salida única, dificultando la lectura y el razonamiento sobre el código.
Fundamento Teórico 7: Variante de bucle

Una variante de bucle (loop variant) es una expresión de valor entero no negativo asociada a un bucle que satisface dos condiciones:

  1. Decrece estrictamente en cada iteración: su valor después de ejecutar el cuerpo del bucle es estrictamente menor que su valor antes.
  2. Está acotada inferiormente por cero: no puede tomar valores negativos.

Estas dos condiciones juntas garantizan que el bucle termina en un número finito de iteraciones, ya que una sucesión de enteros no negativos que decrece estrictamente no puede ser infinita.

En la práctica, la variante suele ser un contador, la distancia entre dos valores que convergen, o el número de elementos que quedan por procesar. Por ejemplo, en un bucle que recorre los dígitos de un entero n dividiéndolo por 10 en cada iteración, la variante es el propio valor de n: decrece estrictamente y llega a 0 en un número finito de pasos. La existencia de una variante de bucle es la herramienta formal para demostrar que un bucle termina.

Fundamento Teórico 8: Invariante de bucle

Un invariante de bucle (loop invariant) es una propiedad lógica sobre el estado del programa que es verdadera antes de la primera iteración y se mantiene verdadera al final de cada iteración. Como consecuencia, también es verdadera cuando el bucle termina, momento en que —combinada con la negación de la condición del while— permite deducir que el resultado calculado es correcto.

El invariante captura formalmente qué está haciendo el bucle: no cómo lo hace paso a paso, sino qué propiedad acumula o preserva en cada iteración. Por ejemplo, en un bucle que calcula la suma \(\sum_{k=1}^{n} k\), el invariante es que al final de la iteración \(i\) la variable suma contiene el valor \(\sum_{k=1}^{i} k\).

La existencia de un invariante de bucle válido es la herramienta formal para demostrar que un bucle calcula lo que se pretende calcular, es decir, su corrección parcial.

La variante y el invariante de bucle son las herramientas teóricas fundamentales del razonamiento formal sobre bucles. La variante garantiza que el bucle termina; el invariante garantiza que calcula lo correcto.Si se puede exhibir una variante y un invariante válidos, se ha probado rigurosamente que el bucle termina y que su resultado es el esperado.

2.6.2 El bucle for (iteración definida) y el objeto range()

El bucle for en Python itera sobre los elementos de una secuencia, por ello se dice que es una iteración definida. Este es un caso donde Python difiere conceptualmente de lenguajes como C o C++. En esos lenguajes, un for suele ser un while disfrazado con un contador numérico (ej. for(i=0; i<10; i++)).

En Python, el for es en realidad un bucle “for-each” (para cada elemento). Su base no es una condición matemática, sino el consumo sistemático de los elementos de un objeto iterable. Un objeto iterable es cualquier objeto que puede entregar sus elementos de uno en uno en un orden definido y sobre el que se puede usar un bucle for.

El ejemplo más inmediato de objeto iterable son los objetos de la clase range. Mediante objetos range se generan secuencias de enteros que constituyen la forma habitual de controlar el número de repeticiones en un bucle for.

El tipo range() genera secuencias de enteros de las tres formas siguientes:

Llamada Secuencia generada
range(n) 0, 1, 2, …, n−1
range(a, b) a, a+1, …, b−1
range(a, b, paso) a, a+paso, a+2·paso, … mientras el valor sea < b
Concepto Clave 7: La anatomía del objeto range

Cuando escribes r = range(0, 10, 2), Python no crea ni almacena en memoria una secuencia con los números 0, 2, 4, 6, 8. Eso sería ineficiente. En su lugar, el objeto range solo almacena tres enteros:

  • start (inicio)
  • stop (fin)
  • step (salto)

Los enteros se producen uno a uno a medida que el bucle los solicita (lazy evaluation). Gracias a esto, range(10) y range(1000000000) ocupan exactamente la misma cantidad mínima de memoria.

Las f-strings (cadenas formateadas) son la forma más moderna, legible y rápida de insertar variables y expresiones dentro de cadenas de texto en Python.         resultado = a / b
    else:
        print("Error: división por cero.")
        resultado = None
else:
    print(f"Operación '{op}' no reconocida.")
    resultado = None

if resultado is not None:
    print(f"{a} {op} {b} = {resultado:.6g}")

Para probar los ejemplos de uso de la función input(), es necesario ejecutar el código en un entorno que soporte la entrada interactiva, como un IDE (Visual Studio Code local o en un Codespace de GitHub) que permita la interacción con el usuario. En entornos de ejecución no interactivos, como algunos notebooks o plataformas en línea, la función input() puede no funcionar correctamente.

Por ello para los ejemplos anteriores con input():

  • genere un fichero de Python test_input.py,
  • copie el código en los ejemplos y peguelo en ese fichero,
  • ejecútelo para ver la interacción en la terminal.

Para hacer este proceso más cómodo ya está disponible un repositorio plantilla con el fichero test_input.py integrado. Aquí tenéis el enlace:

Una vez allí:

  1. En Repository Name dé un nombre al repositorio que incluya vuestro nombre (por ejemplo: ejercicios-tema-2-NombreApellido).
  2. Opcionalmente, agregue una descripción en Description (por ejemplo: Ejercicios del tema 2).
  3. Baje hasta ver el botón verde Create repository y haga clic en él. Esto creará un repositorio nuevo en su cuenta de GitHub con el contenido del repositorio plantilla.
  4. Una vez creado, haced clic en <> Code, después en Codespaces y seleccionad Create codespace on main
  5. Espere a que se configure el entorno de desarrollo, abra el fichero test_input.py y ejecute el código para probar la interacción con input().
