Tema 7: Gestión de Datos y Ficheros

Hasta ahora, todos los datos de nuestros programas vivían en la memoria: las listas, los diccionarios y los objetos desaparecen en cuanto el programa termina. Para que los datos persistan (guardar resultados, compartirlos, analizarlos después) hay que escribirlos en ficheros. Y la mayoría de los datos con los que trabajaremos no los generará nuestro programa: llegarán en ficheros creados por otros (un sensor, una hoja de cálculo, el registro de una partida del Pong de la práctica).

Este tema recorre el camino completo: localizar un fichero (rutas), leer y escribir texto, leer y escribir los dos formatos de intercambio de datos más habituales (CSV y JSON) y, por último, analizar y limpiar datos tabulares con la biblioteca pandas (McKinney 2022).

Fundamento Teórico 1: Fichero

Un fichero es una secuencia de bytes guardada en un dispositivo de almacenamiento (disco, memoria USB, la nube) e identificada por un nombre dentro de un sistema de directorios (carpetas) organizados en árbol. Un fichero de texto es un fichero cuyos bytes representan caracteres según una codificación (en este curso, siempre UTF-8); cualquier otro fichero es un fichero binario (imágenes, ejecutables, PDF…).

Las celdas de este tema se ejecutan en el navegador, que tiene su propio sistema de ficheros virtual: lo que escribas en una celda se puede leer en otra, pero desaparece al recargar la página. La página carga además, en la carpeta datos/, tres ficheros de ejemplo que usaremos a lo largo del tema. Las celdas comparten el mismo entorno de Python: ejecútalas en orden.

7.1. Ficheros y rutas

7.1.1 Rutas absolutas y relativas

Para abrir un fichero hay que indicar su ruta (path): el camino que lleva hasta él a través del árbol de directorios.

Concepto Clave 1: Rutas absolutas y relativas
  • Una ruta absoluta empieza en la raíz del sistema de ficheros: /workspaces/t07-ficheros/datos/partida.csv (Linux, macOS, Codespaces) o C:\Users\ana\datos\partida.csv (Windows).
  • Una ruta relativa se interpreta a partir del directorio de trabajo (current working directory) del programa: datos/partida.csv significa «la carpeta datos dentro del directorio de trabajo».

Los nombres especiales . y .. designan el directorio actual y el directorio padre: ../datos/partida.csv sube un nivel antes de entrar en datos.

El directorio de trabajo depende de desde dónde se ejecuta el programa, no de dónde está guardado el fichero .py. En un Codespace, la terminal se abre en la raíz del proyecto (/workspaces/<nombre-del-repositorio>), y es desde ahí desde donde se ejecutan uv run python ... y uv run pytest.

7.1.2 El módulo pathlib

pathlib es el módulo de la biblioteca estándar de Python para trabajar con rutas de ficheros y directorios. Existe desde Python 3.4 y es la forma moderna y recomendada, en lugar de manipular rutas como cadenas o usar el antiguo módulo os.path (Python Software Foundation 2025c).

La idea central es que una ruta no es una cadena, sino un objeto de la clase Path (tema 6), con atributos y métodos para consultarla y manipularla. El operador / está sobrecargado (__truediv__, igual que hicimos con + en Fraccion) para unir partes de una ruta:

Concepto Clave 2: Por qué usar pathlib
  • Funciona en cualquier sistema operativo. Path("datos") / "partida.csv" usa / en Linux y macOS y \ en Windows sin que tengas que preocuparte.
  • Todo está en un mismo objeto. Las operaciones habituales son métodos de la ruta: exists(), is_file(), is_dir(), mkdir(), iterdir() (listar un directorio), glob("*.csv") (buscar por patrón)…
  • Funciona con las demás herramientas. open(), csv, json y pandas aceptan directamente objetos Path.

Algunas utilidades frecuentes. Para listar el contenido de un directorio se usan iterdir() (todos los elementos) o glob(patrón) (los que encajan con un patrón, donde * significa «cualquier secuencia de caracteres»):

read_text (y su pareja write_text) leen o escriben un fichero de texto completo en una sola línea. Para ficheros grandes, o para recorrerlos línea a línea, se usa open, que veremos en el apartado 7.2.

Error Frecuente 1: Rutas escritas como cadenas en Windows

En Windows las rutas usan la barra invertida \, que en las cadenas de Python es el carácter de escape: "C:\nuevos\tablas.csv" contiene un salto de línea (\n) y un tabulador (\t). Hay tres soluciones: escribir la cadena raw r"C:\nuevos\tablas.csv", usar barras normales "C:/nuevos/tablas.csv" (Windows las acepta), o, mejor aún, construir la ruta con Path y el operador /, que elige el separador correcto en cada sistema.

Técnica de Depuración 1: FileNotFoundError: ¿desde dónde se ejecuta el programa?

Cuando un programa no encuentra un fichero que sí existe, casi siempre es porque se ha ejecutado desde otro directorio de trabajo y la ruta relativa apunta a otro sitio. Para depurarlo, imprime Path.cwd() y ruta.resolve() (la ruta absoluta a la que apunta ruta) justo antes de abrir el fichero. Si el fichero debe buscarse junto al script, independientemente de desde dónde se ejecute, usa Path(__file__).parent / "datos" / "partida.csv".

7.2. Lectura y escritura de texto

7.2.1 Abrir un fichero: open y la instrucción with

La función open(ruta, modo, encoding=...) abre un fichero y devuelve un objeto fichero con métodos para leer o escribir. El modo indica qué se va a hacer:

Modo Significado Si el fichero no existe Si el fichero existe
"r" lectura (por defecto) FileNotFoundError se lee desde el principio
"w" escritura se crea se borra su contenido
"a" añadir al final (append) se crea se escribe a continuación
"x" creación exclusiva se crea FileExistsError
Concepto Clave 3: La instrucción with

Un fichero abierto debe cerrarse cuando se termina de usar: hasta entonces, lo escrito puede no haber llegado al disco y el sistema operativo mantiene recursos reservados. La instrucción with cierra el fichero automáticamente al salir del bloque, incluso si se produce una excepción dentro de él:

with open("datos/salida.txt", "w", encoding="utf-8") as f:
    f.write("Hola\n")
# aquí el fichero ya está cerrado

Es la forma recomendada de trabajar con ficheros en Python: con ella no hace falta llamar a f.close(), y no hay forma de olvidarlo.

La codificación: el argumento encoding

Un fichero de texto guarda bytes, no caracteres. La codificación (encoding) es la regla que traduce cada carácter a uno o varios bytes al escribir, y los bytes de vuelta a caracteres al leer. Las codificaciones más habituales son:

Codificación Caracteres que representa Observaciones
"utf-8" todos los de Unicode (cualquier idioma, símbolos matemáticos, emojis) de 1 a 4 bytes por carácter; el estándar de la web, de Linux y de macOS
"ascii" solo 128 caracteres: letras sin acentos, dígitos y signos básicos 1 byte por carácter; UTF-8 coincide con ASCII en estos caracteres
"latin-1" (ISO-8859-1) los de las lenguas de Europa occidental (á, ñ, ç, à…) 1 byte por carácter; no incluye el símbolo €
"cp1252" (Windows-1252) como Latin-1, más algunos símbolos como € codificación tradicional de Windows en Europa occidental
"utf-16" todos los de Unicode 2 o 4 bytes por carácter; habitual internamente en Windows

Un mismo texto da bytes distintos según la codificación, y leer con una codificación distinta de la usada al escribir produce caracteres erróneos o un error:

Error Frecuente 2: Indica siempre encoding="utf-8"

Si no se indica encoding, open usa la codificación por defecto del sistema operativo, que en Windows ha sido tradicionalmente cp1252 y en Linux y macOS es utf-8. El mismo programa puede funcionar en un ordenador y fallar en otro, con caracteres extraños (mÃ¡s en lugar de más) o con un UnicodeDecodeError. En este curso escribiremos siempre encoding="utf-8" al abrir ficheros de texto.

7.2.2 Escribir texto

Hay tres formas habituales de escribir texto en un fichero abierto f:

  • f.write(cadena) escribe la cadena tal cual y no añade el salto de línea, que hay que escribir explícitamente con "\n". Es la forma más básica.
  • f.writelines(lista) escribe una lista (o cualquier iterable) de cadenas, una detrás de otra. Tampoco añade saltos de línea: cada cadena debe incluir su "\n".
  • print(..., file=f) es la función print de siempre, pero dirigida al fichero en lugar de a la pantalla. Sí añade el salto de línea al final, admite varios argumentos (que separa con un espacio) y es cómoda con f-strings.

7.2.3 Leer texto

Hay tres formas habituales de leer un fichero de texto abierto f:

  • f.read() devuelve el contenido completo del fichero como una sola cadena.
  • f.readlines() devuelve una lista de cadenas, una por línea, cada una con su "\n" final.
  • for linea in f recorre el fichero línea a línea: en cada iteración, linea es la cadena de la línea siguiente, también con su "\n".

En el ejemplo, repr muestra el "\n" que acompaña a cada línea y que normalmente no se ve:

Fundamento Teórico 2: Un fichero es un flujo de datos

Recorrer un fichero con for linea in f es un algoritmo de una sola pasada (tema 5): Python lee una línea cada vez, sin cargar el fichero entero en memoria. Es la forma adecuada de procesar ficheros muy grandes, como los registros de millones de mediciones. En cambio, read() y readlines() cargan el fichero completo (procesamiento por lotes).

Procesar las líneas: de texto a números

Lo que se lee de un fichero de texto son cadenas: la primera línea de primos.txt es '2\n', no el número 2. Para operar con los valores hay que dar dos pasos en cada línea: limpiar la cadena con strip(), que elimina el "\n" y los espacios de los extremos, y convertirla con int() o float():

Error Frecuente 3: Lo que se lee de un fichero de texto son cadenas

Un fichero de texto no guarda números, sino caracteres. Lo que devuelve la lectura siempre es str: "17\n" + "1" da "17\n1", no 18. Hay que convertir explícitamente con int() o float(), y para eliminar el salto de línea y los espacios de los extremos se usa linea.strip().

Error Frecuente 4: El modo "w" borra el fichero

Abrir un fichero existente en modo "w" lo vacía inmediatamente, antes de escribir nada. Para añadir líneas a un fichero sin perder su contenido se usa el modo "a". Si no quieres sobrescribir por accidente un fichero existente, usa el modo "x", que lanza FileExistsError en ese caso.

7.3. Ficheros CSV y JSON

7.3.1 CSV: datos tabulares

Fundamento Teórico 3: Formato CSV

Un fichero CSV (Comma-Separated Values) es un fichero de texto que representa una tabla: cada línea es una fila y, dentro de cada fila, los valores de las columnas se separan con comas. La primera línea suele ser la cabecera, con los nombres de las columnas. Es el formato de intercambio más extendido para datos tabulares: lo leen y escriben todas las hojas de cálculo, los gestores de bases de datos y los lenguajes de programación.

El fichero datos/partida.csv registra una partida de Pong con una estructura parecida (simplificada) a la de los registros de la práctica: una fila por tick con el estado del juego.

Separar cada línea con linea.split(",") funciona en casos sencillos, pero falla si algún valor contiene una coma (por ejemplo, "Palma, Mallorca" entre comillas). El módulo csv de la biblioteca estándar resuelve todos esos casos (Python Software Foundation 2025a).

Escribir un CSV con csv.writer

csv.writer escribe filas a partir de listas o tuplas. El argumento newline="" de open es necesario para que el módulo csv controle él mismo los saltos de línea (en Windows, sin él aparecen líneas en blanco intercaladas).

7.3.2 JSON: datos jerárquicos

No todos los datos son tablas. El registro de una partida tiene información general (los nombres de los bots, el resultado) y una lista de intercambios, cada uno con sus propios campos: es una estructura anidada, en forma de árbol.

Fundamento Teórico 4: Formato JSON

JSON (JavaScript Object Notation) es un formato de texto para datos jerárquicos, basado en dos estructuras que pueden anidarse a cualquier profundidad: objetos (pares "clave": valor entre llaves) y arrays (listas de valores entre corchetes). Es el formato estándar de intercambio de datos en la web y en la configuración de programas (como el devcontainer.json de nuestros repositorios).

El módulo json de la biblioteca estándar traduce entre JSON y Python (Python Software Foundation 2025b). Los tipos de JSON se corresponden de forma natural con los de Python:

JSON Python
objeto {"clave": valor} dict
array [1, 2, 3] list
cadena "texto" str
número 42, 3.14 int, float
true, false True, False
null None

7.4. Pandas: manipulación y limpieza de datos estructurados

Con el módulo csv hemos tenido que escribir un bucle para cada consulta y convertir los valores a mano. Para analizar datos tabulares, la herramienta estándar en Python es pandas (The pandas development team 2025), que carga una tabla completa en memoria y permite consultarla y transformarla con operaciones sobre columnas enteras, sin escribir bucles.

Fundamento Teórico 5: DataFrame y Series

Un DataFrame es una tabla con columnas con nombre, cada una con su propio tipo de datos (int64, float64, object para cadenas…). Cada columna es una Series: una secuencia de valores del mismo tipo con un índice que identifica las filas (por defecto, 0, 1, 2, …).

Las operaciones de pandas son vectorizadas: se aplican a todos los valores de una columna a la vez. df["ball_x"] / 800 divide los 2 652 valores de la columna sin escribir ningún bucle.

pandas no forma parte de la biblioteca estándar. En el navegador, esta página lo carga automáticamente; en un Codespace, está en el grupo data del pyproject.toml y se instala con uv sync --all-groups. Por convención se importa con el nombre corto pd.

7.4.4 Agrupar y agregar: groupby

La operación más potente de pandas es agrupar las filas según el valor de una columna y resumir cada grupo con una función de agregación (count, sum, mean, max…). Es la versión vectorizada del patrón de conteo con diccionarios del tema 5.

Un DataFrame también se puede construir desde datos ya cargados en Python: una lista de diccionarios (como los intercambios del JSON) se convierte en una tabla con una columna por clave.

7.4.5 Limpieza de datos

Los datos reales casi nunca llegan limpios: faltan valores, hay filas duplicadas, aparecen valores imposibles (un sensor que marca -999 cuando falla) o texto donde debería haber números. El fichero datos/mediciones.csv contiene mediciones de tres estaciones meteorológicas con todos esos problemas:

La columna temperatura es de tipo object (texto), no float64: basta un valor no numérico (error) para que pandas no pueda leerla como números. Las celdas vacías aparecen como NaN (Not a Number), el valor que usa pandas para los datos ausentes.

Concepto Clave 4: Pasos de una limpieza de datos
  1. Convertir los tipos: pd.to_numeric(columna, errors="coerce") convierte una columna a números y sustituye por NaN lo que no se pueda convertir.
  2. Eliminar duplicados: drop_duplicates().
  3. Marcar valores imposibles como ausentes, según el significado de los datos (una humedad relativa no puede superar el 100 %).
  4. Decidir qué hacer con los ausentes: eliminar las filas (dropna()), rellenarlos (fillna(valor)) o dejarlos y que los cálculos los ignoren (mean(), sum()… omiten los NaN por defecto).

Cada decisión de limpieza modifica los resultados del análisis, así que debe poder justificarse y quedar documentada en el código.

Con los datos limpios, el análisis es directo. mean() ignora los NaN, y count() dice cuántos valores válidos ha usado cada media:

Error Frecuente 8: NaN no es igual a nada, ni a sí mismo

Por definición (norma IEEE 754 de coma flotante), NaN == NaN es False. Por eso df["temperatura"] == float("nan") no encuentra nunca los valores ausentes. Para detectarlos se usan los métodos isna() y notna().
